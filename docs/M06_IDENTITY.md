# M06 — Local MT5 account binding, not remote broker attestation

The official MetaQuotes Python `account_info()` exposes login, server, and trade mode. This implementation uses these **inside the local read-only adapter**. It computes an HMAC account binding ID; no login/server number is put into the Trading Room event journal, LLM prompts or published CI artifacts. Source: https://www.mql5.com/en/docs/python_metatrader5/mt5accountinfo_py

The owner-started `mt5-probe` and `watch` commands use a locally generated 32-byte key at `.local/mt5_identity.key` by default. The `--identity-key-file` option is available if the owner wants a private OS-backed directory. The file is excluded by `.gitignore`. On Unix, the key is created with 0600 permissions and permissive mode is rejected. **On Windows, file protection depends on the user's folder ACL**. Do not check this key into Git, send it to a hosted LLM, or copy it into logs. If the file changes, existing account bindings will no longer match and the watcher fails closed.

Every signed read-only snapshot carries an HMAC over the original captured payload and a separately derived HMAC over **account login+server**. The watcher verifies before LLM calls or writing a new candle baseline, then checks that the account binding matches the previous baseline and that DEMO/REAL/CONTEST has not changed. A different login/server returns ACCOUNT_ID_CHANGED even if the trade mode is unchanged. A legacy M05 baseline with no account binding returns ACCOUNT_BINDING_REQUIRED: **no automatic migration, no hidden reset**. A reviewed, explicit account-rebinding workflow is outside this milestone.

Important limits:
- HMAC detects changes by parties without access to the local key, but does not cryptographically prove quotes originated from MetaQuotes or the broker. An attacker with control of the device/key can forge signed data.
- Provenance is valid only for the single local adapter capture point. JSON loaded from third-party files or generated by an LLM is not automatically trusted by this watcher.
- The program does not verify OS-level broker terminal identity/Windows user profile or remote market attestation; those require real owner terminal acceptance.
- This does not add any order capabilities; market monitoring remains READ_ONLY and all research NO_TRADE.
- GitHub Actions runs synthetic data/provider tests on GitHub-hosted Linux and Windows, not the owner's local CI.
